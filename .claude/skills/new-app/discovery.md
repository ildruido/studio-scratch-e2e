# New app: discovery path and start building

_Branch file of the `new-app` skill. Read it only when the app has no stack yet, or the App Creator says "start building". The numbered steps are in `SKILL.md`._

## Discovery path (no stack chosen yet)

For an app that has no stack, starter code or CI yet. It records "not decided yet" as `TBD` instead of made-up values.

- Steps 1 and 3 as usual. Step 4: only `install` (no stack pack, no `npm install`); then copy `app-studio/packs/base/starter/.github/workflows/harness.yml` and `.nvmrc` into the repo unchanged, so the `health` check runs on PRs (a later `pack add base` accepts them as they are).
- Step 5: `node .claude/hooks/app-setup.mjs profile init --discovery --name "<App name>" --prefix <XX> --repo <owner/repo> ["Field=value" ...]` writes **Phase `discovery`**, the real App name, Id prefix and Repo, and `TBD (decided at build start)` for Stack, Release target, Preview target, Capabilities, AI, AI plan, Access model and Storage shape; a real answer already given goes in as a `Field=value` argument. You still fill by hand what the App Creator has already told you (the title, the User row, the product paragraph) and write `TBD` for AI public use, the Domain rules line and each Stack notes line; `health` fails while a template placeholder is left. Never invent a value to satisfy the check. A real answer the App Creator already gave (a domain rule, "AI off") is recorded as such.
- **Offer guided discovery, as one question.** Ask the App Creator whether they want the discovery method before building: Claude interviews them, checks the idea against real users and the market, and writes one short document at a time (foundation, personas, hypotheses, MVP, a reviewed handoff). Recommend **yes** for a new product idea, where who it is for and whether they want it is still open; recommend **no** for a small tool that only needs a PRD. One answer covers both modules (`discovery` needs `research`). Discovery without them stays a normal choice.
  - **Yes:** `node .claude/studio/studio-sync.mjs pack add discovery` (it adds `research` too), then `node .claude/hooks/app-setup.mjs discovery-profile init --product "<the product in one line>" --users "<the target users in one line>"`, in the App Creator's words (ask if they have not said; never invent them; more options in `.claude/packs/discovery/STACK.md`). Put what the App Creator has said about the idea into `docs/discovery/starting-idea.md`, in their words. **Skip step 8:** the PRD and the backlog are written at "start building", from the MVP and the roadmap that discovery produces.
  - **No:** step 8 as usual (`prd-intake`: `docs/PRD.md` and `docs/BACKLOG.md`; the AI, access and storage questions may be answered "not decided yet" and recorded as `TBD` in the decision log).
- Step 9: `node .claude/studio/studio-sync.mjs check` and `health` only. Step 10: the ruleset requires only `health`; skip `CI gate`. In discovery `build-feature`, `test-handoff` and `release` stop on their own (`studio-sync.mjs phase --build-only`).
- End with step 12's report and say the app is in discovery. With the modules, say what comes first: one document per thread, in the order of `.claude/packs/discovery/WORKFLOW.md`, starting with the product foundation; every session's start-up note says how many exit criteria are done and which document is next.

## Start building (discovery to build)

Run only when the App Creator says "start building" (never because a stack was merely mentioned). An app **has the discovery module** when `.claude/packs/discovery/` exists; `<docs>` is then the Docs folder of the Discovery profile in `CLAUDE.md`. Steps marked "module" apply only to such an app.

1. **Exit gate first (module).** Follow the `exit-gate` skill's steps 1 to 6 (up to its merged report) before anything else here, because it needs Phase `discovery`; skip its step 7, which step 2 here replaces. The gate informs, it never blocks: you go on whatever it says, and the gaps go in front of the App Creator in step 2.
2. **Ask the stack question.** One message: the gate's result in a few lines (what is done, what is missing; module), then step 2's product question (artifact prototype, web app or static site). With an architecture handoff (`<docs>/architecture-handoff.md`), its stack recommendation is the recommended answer, with its reason in one line; without one, step 2's default. The App Creator's answer decides the stack packs. If the gate was not ready, their answer is also the decision to build with those gaps (they may instead say to close them first: then stop and hand back). Record each as its own decision with `node .claude/hooks/decisions.mjs add "<title>" --decision ".." --why ".." --by "the App Creator" --fetch`.
3. **Fill the App profile.** With a handoff, apply its App profile draft first: `node .claude/hooks/app-setup.mjs profile set` with the draft's pairs, except any the stack answer changed, and its proposed Domain rules. Then replace every `TBD` that is left with a real answer (the AI, Access model and Storage shape questions are asked now, per `prd-intake` "Features"; never guess one; Release target and Preview target say where releases and previews will go, and step 11 adds the address; AI public use says "not needed" when its condition does not apply), write the product paragraph (module: from `<docs>/product-foundation.md`, with one line saying the discovery documents in `<docs>` are history), and set **Phase** to `build`. For a static site, the profile rows are the ones in `static-site.md`.
4. **Add the stack:** `pack add <packs> --slug <repo> --title "<App name>"`, `npm install`, and steps 6 and 7 as written. Then make sure `.prettierignore` skips the prototypes: it has the line `docs/**/*.html` for a Docs folder under `docs/` (new apps get it from the pack; add it if missing), and `<docs>/**/*.html` for any other Docs folder. Otherwise a prototype saved as an HTML file turns the first `npm run check` red. If discovery wrote a roadmap, recommend the `roadmap` module in step 7's question.
5. **Close discovery (module).** `node .claude/studio/studio-sync.mjs pack remove discovery`, then `node .claude/hooks/app-setup.mjs discovery-profile close`: the discovery skills and workflow leave the app, the Discovery profile section leaves `CLAUDE.md`, and `<docs>/status.md` is marked as history. The `research` module stays, and so does every document in `<docs>` and `docs/research/`, as the app's own files. The decision log stays where it is (App profile, Decision log row).
6. **Requirements (module):** step 8, with `<docs>/mvp.md` and `<docs>/roadmap.md` as the input (`<docs>` is the folder `close` printed, now that the profile is gone) (`prd-intake` reads its `from-discovery.md`). From here the backlog is the only plan. An app without the module already has its PRD and backlog from the discovery path.
7. Step 9 as written: `health` fails while any `TBD` is left. Add `CI gate` to the ruleset's required checks (step 10's clicks), then step 11, and step 14.
8. Give the coordinator step 12's report again (Project instructions, settings, Admin's checklist), since the app now has a stack, so the instructions and the checklist change.
