# Harness sync: pack starter files and Project instructions

_Branch file of the `harness-sync` skill. Read it only when `sync` or `check` reports held-back or edited pack starter files, says "Project instructions template changed", or the report ends with "Large jump"._

5. **Pack starter files** (CI workflow, configs, server, platform adapters) are the app's own code. `sync` refreshes the ones you never edited and adds files new in a pack; for the rest the check says "edited here". If it says starter files are **held back** (the app calls a module's capability, e.g. `sample()`, without that module), add the module it names in the same sync (`pack add ai`, or `pack add ai-web` on the web) and follow its **App action** in the report. Read the pack's entry in the report, diff the file against `app-studio/packs/<name>/starter/…` (placeholders `{{slug}}` and `{{title}}` stand for the app's name), merge what applies, then run `node .claude/studio/studio-sync.mjs ack` so the note stops.

7. **Project instructions.** If the `sync` or `check` output says "Project instructions template changed", an app's instructions live in Project settings, so no sync can update them. Tell the coordinator in your hand-back with the ready prompt the tool printed; the coordinator compares and updates its own instructions (keeping app-specific text). Once the coordinator confirms, run `node .claude/studio/studio-sync.mjs ack instructions` and commit the lock. Until then the start-up check keeps reminding.

9. **A large jump** (the report ends with "Large jump": the app skipped 20 releases or more). It is still one sync, never one release at a time: the update from app copies as old as 0.18 is tested in app-studio. What is different:
   - **Preview first.** Run `sync` with `--dry-run` and put its lists (not the release lines) in the PR description, so the App Creator can see what moved. Do not wait for an OK unless one of the points below needs a decision.
   - **The report is short on purpose.** It lists the releases that changed what apps get and counts the rest. Tell the App Creator in two or three sentences what changes for them; do not pass on the release lines.
   - **App actions from skipped releases.** Do each one once. Several releases may ask the coordinator to update the Project instructions: that is one step, the ready prompt (part 7). A step that names another kind of app ("static-site apps only") applies only to that kind. A step that says the wording "arrives with `harness-sync`" is already done by this sync.
   - **Admin actions from skipped releases.** One about app-studio's own Project or its "app-studio" environment is the App-Studio Owner's and is not relayed. Pasting the setup script into the "app-studio apps" environment is relayed only if this app's threads do not open with "Studio harness loaded".
   - **`CLAUDE.md`.** The sync replaces only the harness-owned sections. A section listed as "left as they are (merge by hand)" has the app's own wording: merge the template's text into it and keep what is the app's. Everything else stays, also old template text the current template no longer has (the long Harness, CI and Cloud sessions sections now live in this skill's `harness.md`). Where such old text contradicts the template, replace it with the template's and list what you replaced in the PR; shortening the file beyond that is a separate backlog item for the App Creator to order, not part of the sync.
   - **`.claude/settings.json`** is the app's own and is never changed by a sync. If `health` names a hook that is missing, add it from app-studio's `plugins/studio/templates/settings.json`.
   - **Pack starter files.** Expect more notes than usual: part 5. An app that never took a pack's starter files (it predates them and keeps its own CI, configs and code) gets none added: the first sync records those packs in the lock (`ownStarters`) and each pull says how many files it left out.
   - **Afterwards.** Before the PR, `health` must pass and `npm run check` must still pass as it did before the sync. After the merge, a fresh thread must open with "Studio harness loaded"; say in the hand-back whether it did.
